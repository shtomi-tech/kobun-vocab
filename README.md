# 古文演習（単語 4択 ＋ 活用ドリル）

古文単語の4択演習と、古典文法を学習順に進める1つの静的アプリです。段階1（古文単語）と段階2（古典文法）は最初から並行して進められる独立トラックです。段階1は必須200語を20問×10セットで進め、誤答数に関係なく各セットを終了し、10セット後に200語からランダム30問の確認テストを行って24問以上（80%以上）で段階1修了と判定します（文法への解放条件ではありません）。段階3・段階4は従来どおり直列で、段階2（文法混合確認まで）を完了すると段階3「敬意の方向 → 省略主語 → 短文統合 → 敬語読解チェック」が、段階3を完了すると段階4「宮廷生活 → 恋愛・婚姻 → 年中行事 → 古文常識チェック」が解放されます（いずれも段階1の完了状況とは無関係）。

- **古文単語**モード：古語（かな＋漢字＋品詞）→ 意味の4択。章別演習、苦手復習、進捗保存、生徒別クラウド同期（共有URL）に対応。
- **古典文法**モード：文法ロードマップから必修タスクを順に進める。段階2の通常問題は各タスクの通し演習で全問を1回以上正解、識別フローは4択・実践の全問1回正解、文法混合確認は30問中24問以上を終了条件とする。段階3の敬語読解は3グループ各4問を累計2回正解し、最後の12問チェックで10問以上を取ると終了する。段階4の古文常識は、宮廷生活・恋愛／婚姻・年中行事の3グループ各4問を累計2回正解し、最後の12問チェックで10問以上を取ると終了する。

### 段階2（古典文法）の必修

文法に詳しくない生徒が土台から積み上げられるよう、8つの必修を順に解放します（2026-07-25改訂）。

| # | 必修 | 内容 |
|---|---|---|
| 1 | 文法の入口 | 歴史的仮名遣いと読み／文節・自立語と付属語／活用形の見分け／接続という考え方 |
| 2 | 用言の活用 | 用言13語の活用表／品詞・活用・係り結び／用言の攻略 |
| 3 | 助動詞の活用・接続 | 助動詞28語の活用表／助動詞の攻略①③ |
| 4 | 助動詞の意味を決める | る・らる／す・さす・しむ／む・むず・じ／まし／き・けり／つ・ぬ／たり・り／らむ／けむ／べし・まじ／なり（断定・存在） |
| 5 | 助詞 | 助詞の攻略／ば・より・格助詞「の」・だに・係り結びの特殊構文・終助詞 |
| 6 | 同形語の識別 | ぬ・ね／る・れ／なり（伝聞推定・断定）／なむ／に |
| 7 | 敬語 | 敬語の攻略／給ふ・奉る・参る・侍り・候ふ・補助動詞の訳・敬意の方向 |
| 8 | 文法混合確認 | 必修1〜7の4択からランダム30問（24問以上で合格） |

同形語の識別を助詞のあとに置いているのは、「に」「なむ」の識別が助詞の知識を前提にするためです。識別はすべて「手順の内容理解 → 4択 → 実践（傍線部の意味4択）」の順で進みます。通常問題は各タスクの通し演習で全問を1回以上正解すると完了になります。文法混合確認は出題形式をそろえるため4択に限定し、活用表の行埋めと実践問題は母集団から除いています。

`static/app.js` は段階1（古文単語）／段階2〜4（古典文法）のモード切り替えのみを管理し、段階間のゲートは持ちません（両モードのタブは常に選択できます）。`static/mode-katsuyo.js` が段階2〜4のロードマップと、段階3・4のゲート（段階2完了で段階3、段階3完了で段階4。いずれも段階1の完了状況とは無関係）を管理します。`static/learning-map.js` が、段階1・2の並行トラックと段階3・4の直列フローを1つの学習マップとして描画します。進捗の保存キー（localStorage）は `kobun_vocab_progress_v1` / `kobun-katsuyo-progress-v1`、文法ロードマップのチェックポイントは `kobun-katsuyo-path-v1` です。クラウド同期は単語モードのみ（appId `kobun-vocab`）。

> **注意（2026-07-25）**: 段階2の必修タスクIDを刷新したため、この改訂より前に文法を進めていた生徒の**文法の進捗は未完了に戻ります**。段階1（古文単語）の進捗とクラウド同期は影響を受けません。

## 起動

ポータルから開きます。

```powershell
py C:\Users\shtom\dev\portal\launcher.py
```

静的ファイルとして直接確認する場合は、ローカルサーバー経由で開きます（`fetch` で JSON を読むため、`file://` 直開きは不可）。

```powershell
py -3 -m http.server 8062 --directory C:\Users\shtom\dev\kobun-practice
# → http://127.0.0.1:8062
```

## データ

- `data/vocab.json` … 古文単語帳（単語モード）。
- `data/katsuyo.json` … 助動詞・動詞・形容詞・形容動詞の活用表（必修2・3）。
- `data/kiso.json` … 必修1「文法の入口」の4択問題。
- `data/multiple_choice.json` … 章別の文法4択問題（Chapter 1・2・3・5・7・9）。
- `data/shikibetsu.json` … 必修4「助動詞の意味を決める」の手順本文と問題。置き換え済みの旧「助詞／同形語／敬語」の3手順は `deprecated` キーに退避（アプリからは読み込まれない）。
- `data/shikibetsu-joshi.json` … 必修5の助詞の識別（ば・より・格助詞「の」・だに・係り結びの特殊構文・終助詞）。
- `data/shikibetsu-homograph.json` … 必修6の同形語の識別（ぬね・るれ・なり・なむ・に）。
- `data/shikibetsu-keigo.json` … 必修7の敬語の識別（給ふ・奉る参る・侍り候ふ・補助動詞の訳・敬意の方向）。
- `data/keigo-dokkai.json` … 段階3の敬語読解（敬意の方向・省略主語・短文統合）。
- `data/kobun-joshiki.json` … 段階4の古文常識読解（宮廷生活・恋愛／婚姻・年中行事）。
- `data/jodoshi.json` … 旧助動詞データ（互換用に残置）。
- 教材由来のデータを含みます。公開・配布する前に、素材の扱いを確認します。個人情報は含みません。

必修4の助動詞識別は、登録116問のうち94問を必修ルートで扱います。資料「助動詞問題」のうち、既存の原則範囲に合う21問を優先して実践4択へ反映しました。残り22問は内容を削除せず、必修完了条件に含めない「追加練習」として残しています。必修ルートは各識別の手順・条件・対比・実践を確認し、追加練習は必要なときだけ取り組めます。

必修5の助詞識別は、登録53問のうち41問を必修ルートで扱います。残り12問は追加練習として残し、格助詞「の」の5用法（連用修飾格・準体格・連体修飾格・同格・主格）を必修ルートに追加しています。

必修6の同形語識別は、登録69問のうち50問を必修ルートで扱います。今回、「ぬ・ね」と「る・れ」の指定例を7問ずつ反映しました。残り19問は追加練習として残し、条件28問と対比5問は必修に含め、手順と統合問題を圧縮しています。

必修7の敬語識別は、登録45問のうち39問を必修ルートで扱います。残り6問は追加練習として残し、条件19問と対比5問は必修に含め、実践問題を中心に圧縮しています。

必修1の文法の入口は、登録28問のうち26問を必修ルートで扱います。残り2問は追加練習として残し、歴史的仮名遣いと活用形の確認問題を1問ずつ圧縮しています。

文法4択は、登録90問のうち66問を必修ルートで扱います。残り24問は章ごとの追加練習として残し、各章の代表的な知識・適用問題を必修に含めます。

## 原則集との対応

文法問題は `C:\Users\shtom\dev\docs\kobun-principles` の原則カードに紐づけています。各問題の `ruleRefs` に、正答判定の根拠にした `ruleId` を記録します。

```powershell
py -3 C:\Users\shtom\dev\kobun-practice\scripts\quality_check.py --check       # スキーマ・選択肢の偏り・誤答根拠・重複
py -3 C:\Users\shtom\dev\kobun-practice\scripts\check_rule_coverage.py --check # ruleRefs の実在・status:active・カバレッジ
py -3 C:\Users\shtom\dev\docs\kobun-principles\scripts\check_principles.py     # 原則カード側の検査
```

対応表は `docs/rule-coverage.txt`（`check_rule_coverage.py` の出力）にあります。原則カードが未整備のまま出題している分野は同レポートの末尾に一覧され、原則集の `INBOX.md` にも候補として記録しています。

## 由来

このリポジトリは、もともと単語演習のみだった `kobun-vocab` に `kobun-katsuyo`（活用ドリル）を統合したものです。公開URLとQRコード配布・Supabase生徒別クラウド同期を維持するため、器はこちら（kobun-vocab）側を採用しています。

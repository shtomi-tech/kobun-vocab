# 古典文法演習 v2.1

古典文法を教材目次どおりの6章46講で進める、古典文法専用の静的アプリです。講の中では予習と必修活動をひとつのキューで進め、46講の後に文法混合確認を行います。その後に段階2（敬語読解）、段階3（古文常識）へ進みます。

- **文法ロードマップ**：6章46講。通常問題・識別問題とも、講の必修活動を1回以上正解すると講が完了する。講の復習、章復習、苦手復習を用意する。
- **文法混合確認**：46講とは別のcheckpoint。30問中24問以上で合格し、講の完了数には含めない。発展学習も完了条件から分離する。
- **段階2（敬語読解）**：敬意の方向・省略主語・短文統合の3グループ各4問を累計2回正解し、最後の12問チェックで10問以上を取ると終了する。
- **段階3（古文常識）**：宮廷生活・恋愛／婚姻・年中行事の3グループ各4問を累計2回正解し、最後の12問チェックで10問以上を取ると終了する。

各講には予習資料があり、ロードマップの「この講を始める」から資料を読んで問題へ進める。生徒別クラウド同期（共有URL）にも対応する（`static/config.json` の設定がある場合のみ）。

文法に詳しくない生徒が土台から積み上げられるよう、10の必修を順に並べています。問題は先に選択できますが、12歳でも文の形を先に見抜ける構成です。

| # | 必修 | 内容 |
|---|---|---|
| 1 | 文の骨組み | 歴史的仮名遣いと読み／文節と品詞／文の成分と省略／活用形と係り結び／接続 |
| 2 | 用言の活用 | 活用の種類と所属語／活用の種類の見分け方／用言の活用表を読む／用言13語の活用表／語幹・音便／語幹の用法と訳し分け |

| 4 | 連用形接続の助動詞 | 活用表7語＋り（き・けり・つ・ぬ・たり・けむ・たし の順）／き・けり・つ・ぬ・たり・けむの識別 |
| 5 | 終止形接続の助動詞 | 活用表6語／基本意味（らし）／らむ・べし・まじの識別 |
| 6 | 体言・連体形接続の助動詞 | 活用表3語（なり・たり・ごとし）／なり・その他の識別 |
| 7 | 助詞・呼応・文末 | 助詞の地図／呼応・係り結び・禁止・願望／ば・より・格助詞「の」・だに |
| 8 | 同形語の識別 | ぬ・ね／る・れ／なり（伝聞推定・断定）／なむ／に |
| 9 | 敬語・補助動詞 | 敬語の攻略／給ふ・奉る・参る・侍り・候ふ・補助動詞の訳・敬意の方向 |
| 10 | 文法混合確認 | 必修1〜9の4択からランダム30問（24問以上で合格） |

必修3〜6は、助動詞を接続グループごとに「活用表 → 基本意味 → 識別手順」で完結させます。28語の活用表を先にすべて埋めてから意味へ進むと、形の暗記と意味判断が離れてしまうため、未然形・連用形・終止形・体言連体形の4ブロックに分け、同じ接続の語をひとまとまりで扱います。接続は形と意味をつなぐ軸なので、その考え方と同形語の切り分けは必修1の「接続という考え方 14問」にまとめ、助動詞の必修はそこを土台に進みます。ただし、き・けり／つ・ぬ／たり・り／らむの基本意味は、識別タスクの予習資料と内容がほぼ重複していたため、2026-08-03に識別タスクへ統合し、基本意味の単問は削除しました（ず・まほし・たし・らしは識別タスクが無いため基本意味のまま残しています）。

必修3（未然形接続）内のタスク順は活用表と同じ語順（る・らる・す・さす・しむ・ず・じ・む・むず・まし・まほし）に揃えています。「じ・む・むず」は意味の決め方が同じ（人称で場合分けし、じはむの打消側）なので識別は1タスクにまとめていますが、実践問題の出題順は「じ→む→むず」に並べ替え、語順とタスク内の順序がずれないようにしています。

必修4（連用形接続）内のタスク順も「き・けり・つ・ぬ・たり（完了）・けむ・たし」に揃えています。「たり・りの識別」（完了・存続の意味と見分け方がたりと共通）は旧必修6（体言・連体形接続）にありましたが、たりの直後で学べるよう必修4へ移しました。連動して `data/katsuyo.json` の活用表グループも、り（サ変未然形・四段已然形接続）をg4からg2へ移し、活用表タスクは「連用形接続7語＋りの活用表」「体言・連体形接続3語の活用表」に変わっています。基本意味は語ペアごとの識別直後に置けるよう、き・けり／つ・ぬ／たり・り／たしの4タスクに分割しました（けむには基本意味の単問がありません）。2026-08-03、このうちき・けり／つ・ぬ／たり・りの基本意味は、対応する識別タスクの予習資料（`data/preparation/kobun-04-keri.md`等）と内容が重複していたため削除し、識別タスク1本に統合しました。たしは対応する識別タスクが無いため基本意味の単問のまま残しています。

必修2は「所属語を覚える → 種類の見分け方 → 活用表を選択肢で読む → 活用表を自力で埋める → 語幹・音便 → 訳し分け」の順です。行埋め（用言13語の活用表）は表を自力で再生する課題なので、その前に種類を決める手順と各活用型の並びを4択で確かめます。

同形語の識別を助詞のあとに置いているのは、「に」「なむ」の識別が助詞の知識を前提にするためです。識別はすべて、予習資料で手順を確認してから実践（傍線部の意味4択）に進みます。手順本文は演習中の参照カードとロードマップの折りたたみからも読めます。通常問題は各タスクの通し演習で全問を1回以上正解すると完了になります。文法混合確認は出題形式をそろえるため4択に限定し、活用表の行埋めと識別の実践問題は母集団から除いています。

`static/app.js` は起動と共通キーボードイベントだけを管理する薄いシェルです。`static/mode-katsuyo.js` が6章46講のロードマップ、checkpoint、発展領域、段階2・3のゲートを管理します。文法の進捗保存キーは `kobun-katsuyo-progress-v2`、文法ロードマップの講・checkpoint状態は `kobun-katsuyo-path-v2`、予習の進捗は `kobun-preparation-progress-v1`、クラウド用の文法appIdは `kobun-katsuyo-v2` です。生徒別クラウド同期（共有URL ?s=&t=）はこの文法appIdで行います。

> **注意（v2）**: 旧 `kobun-practice` の文法進捗・公開設定・URLは使用しません。v2は別の保存キーとappIdを使います。
>
> **注意（v2）**: 文法ロードマップの並び替えと必修問題の追加を含むため、v2内の文法進捗は新規に開始します。

## 原則集との対応

文法問題は `C:\Users\shtom\dev\docs\kobun-principles` の原則カードに紐づけています。各問題の `ruleRefs` に、正答判定の根拠にした `ruleId` を記録します。

問題を追加・修正するときは、リポジトリ内の[古文演習の問題作成原則](docs/QUESTION_AUTHORING_PRINCIPLES.md)と、対象分野の active 原則カードを参照します。

```powershell
py -3 C:\Users\shtom\dev\kobun-practice-v2.1\scripts\quality_check.py --check       # スキーマ・選択肢の偏り・誤答根拠・重複
py -3 C:\Users\shtom\dev\kobun-practice-v2.1\scripts\check_rule_coverage.py --check # ruleRefs の実在・status:active・カバレッジ
py -3 C:\Users\shtom\dev\docs\kobun-principles\scripts\check_principles.py     # 原則カード側の検査
py -3 C:\Users\shtom\dev\kobun-practice-v2.1\scripts\check_preparation.py       # 予習投稿の280字・構造検査
py -3 scripts\audit_preparation_checks.py                                     # 10秒確認152件の対応・構造検査
```

対応表は `docs/rule-coverage.txt`（`check_rule_coverage.py` の出力）にあります。原則カードが未整備のまま出題している分野は同レポートの末尾に一覧され、原則集の `INBOX.md` にも候補として記録しています。

## 問題の品質スコアと退役

`scripts/score_questions.py` が、4択・識別の255問を100点満点で採点します。`quality_check.py --check` が止める項目（最長バイアス・誤答根拠の欠落・重複・必修ルート）は既にゲートで防いでいるので、採点はその先の程度問題だけを扱います。配点は A 正答の妥当性35 / B 誤答の質20 / C 手掛かり漏れ15 / D 解説の質15 / E 重複・冗長15。

```powershell
py -3 scripts/score_questions.py --json reports/question-quality.json --output reports/question-quality.md
py -3 scripts/score_questions.py --propose --limit 20
py -3 scripts/score_questions.py --apply --ids <id,id> --note "理由"
py -3 scripts/quality_check.py --check
```

評価の低い問題を出題から外すことを **退役（retire）** と呼びます。`--apply` は正本JSONの該当問題に1行の `"retired"` を差し込むだけで、問題文はそのまま残ります。`static/mode-katsuyo.js` の `pruneRetired` が読み込み時に、出題・必修ID・グループ・識別カバレッジから外します。戻すときは `--restore --ids <id>` を実行します。

退役できない条件は `score_questions.py` と `quality_check.py --check` の両方で確認します。

- グループの問題、またはグループの必修問題が全て無くなる
- 識別カバレッジの指定例になっている（用法ごとに1問が割り当てられているため、退役するなら `coverageTopics` の見直しが要る）
- `status: active` の原則カードを扱う唯一の問題になる
- 文法混合確認の母集団が40問を割る（30問中24問の合格条件が成立しなくなる）

`multiple_choice.json` は `topic`／`step` を持たないため、章が同じというだけでは同じ判断とみなさず、冗長の減点も代替の判定も行いません。選択肢はアプリ側でシャッフルするので、正答位置は採点しません。
